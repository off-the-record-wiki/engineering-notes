# (Clean Architecture 25) - 계층과 경계

#### 흐름 분리

![](https://github.com/user-attachments/assets/730124f4-bb98-415d-80a6-ab9d58a2c383)

1. 경계는 생각보다 많다

* 단순해 보이는 시스템도 들여다보면 독립적으로 바뀌는 축이 여러 개이다. 
* 축마다 높은 수준 쪽에 인터페이스(API)를 두고, 낮은 수준 쪽에서 그걸 구현하면 경계가 생긴다.
* 축이 서로 독립적이면 경계끼리 겹치지 않고, 의존은 모두 핵심 업무 규칙을 향한다.

2. 업무 규칙 안에도 경계가 생길 수 있다

* 데이터 흐름도 단순한 한 줄이 아니다. 여러 축을 따라 갈라지고 높은 수준으로 모이기도 한다.

3. 핵심 딜레마

* 경계를 다 만들면 인터페이스, 데이터 구조, 의존성 관리가 늘어나서 개발과 유지보수 비용이 커진다. 쓰지도 않을 경계는 과잉 설계(YAGNI)이다.
* 경계를 하나도 안 만들면 나중에 필요해졌을 때 코드가 이미 얽혀 있어서 추가 비용이 크고 위험하다.
