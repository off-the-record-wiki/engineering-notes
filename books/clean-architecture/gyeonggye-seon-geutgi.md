# (Clean Architecture 17) - 경계: 선 긋기

#### 경계: 선 긋기

* 경계는 소프트웨어 요소를 서로 분리하고 경계 한 편에 있는 요소가 반대편에 있는 요소를 알지 못하도록 막는다.
* 아키텍트의 목표는 필요한 시스템을 만들고 유지보수하는 데 드는 인적 자원을 최소화하는 것이라는 사실을 상기해야한다.

#### 어떻게 선을 긋고 언제 긋는지?

![](https://github.com/user-attachments/assets/4ccfe1a4-abc0-4e0c-9a75-cf442a67be82)

* 경계(boundary)는 소프트웨어를 나누는 선이다. 중요한 것(업무 규칙)과 중요하지 않은 것(세부 사항) 사이에 긋고, 그 목적은 세부 사항에 대한 결정을 최대한 늦추는 것이다.

1. 무엇과 무엇 사이에 긋나?

* 중요한 것 : 업무 규칙. 예를 들어, 할인 정책, 주문, 유스케이스처럼 시스템이 존재하는 이유다.
* 중요하지 않은 것 : GUI, DB, 웹 프레임워크, 외부 API처럼 업무 규칙을 실행하는 수단이다.
* 판단 기준은 "이게 바뀐다고 업무 규칙이 바뀌어야 하나"이다. 아니면 경계 바깥으로 보낸다.

2. 어떻게 긋나?

* 모든 의존 화살표가 경계를 넘어 안쪽(업무 규칙)으로 향한다.
* 결과적으로 세부 사항은 업무 규칙에 꽂는 플러그인이 된다. GUI, DB, 프레임워크 모두 같은 원리이다.
