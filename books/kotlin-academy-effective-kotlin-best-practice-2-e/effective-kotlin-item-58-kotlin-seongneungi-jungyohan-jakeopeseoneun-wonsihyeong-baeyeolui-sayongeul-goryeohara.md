# (Effective Kotlin Item 58) Kotlin - 성능이 중요한 작업에서는 원시형 배열의 사용을 고려하라

#### 성능이 중요한 작업에서는 원시형 배열의 사용을 고려하라

* 코틀린에서 원시형을 직접 선언할 수는 없지만 래퍼 타입은 내부적으로 최적화되어 원시형으로 바뀌게 된다.
* 원시형은 다음과 같은 특징을 가지고 있다.
  * 가볍다. 원시형이 아닌 객체는 메모리가 추가적으로 필요하다.
  * 빠르다. 접근자를 통해 값을 조회하는 것은 비용이 들며, 객체를 생성하는 것 또한 비용이 발생한다.
* 따라서 데이터 규모가 큰 경우 원시형으로 대체하면 최적화가 이뤄지게 된다.
* 하지만 `List`나 `Set`을 포함한 코틀린 컬렉션은 제네릭이다. 제네릭 타입에 원시형을 넣을 수 없으므로 래핑 타입을 사용해야 한다.
* 표준 컬렉션은 다양한 기능을 제공하고 있으므로 대부분의 경우는 래핑 타입을 사용하는 것이 좋다.
* 그러나 코드 성능이 중요한 부분에서는 메모리 측면에서 더 가볍고 더 효율적인 `IntArray` 또는 `LongArray`와 같은 원시형 배열을 사용하는 것이 좋다.

| 코틀린 타입 | 자바 타입 |
|:---:|:---:|
| `Int` | `int` |
| `List<Int>` | `List<Integer>` |
| `Array<Int>` | `Integer[]` |
| `IntArray` | `intp[]` |

* 성능이 중요한 경우에 원시형 또는 원시형 배열을 사용해 최적화를 이룰 수 있다. 더 적은 메모리를 할당하고 처리 속도도 더 빠르다.
* 하지만 대부분의 경우는 원시형 배열과 래핑 타입 리스트의 성능이 크게 차이나지 않는다. `List`가 훨씬 더 직관적이고 편리하므로 웬만하면 `List`를 사용하는 것을 권장한다.
* 성능을 최적화해야 한다면 래핑 타입 `List`를 원시형 배열로 대체하는 방법을 생각해야 한다.
