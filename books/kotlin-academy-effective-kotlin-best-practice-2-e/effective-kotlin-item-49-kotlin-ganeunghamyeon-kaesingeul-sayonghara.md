# (Effective Kotlin Item 49) Kotlin - 가능하면 캐싱을 사용하라

#### 가능하면 캐싱을 사용하라

* 캐싱(Caching)은 반드시 알고 있어야 하는 성능 최적화 방법 중 하나이다.
* 캐싱은 여러 수준에서 다양한 방법으로 사용된다. 
* 컴퓨터에는 CPU 캐시와 디스크 캐시가 있다. 브라우저에는 웹 페이지에 대한 캐시가 있다. 네트워크 제공자는 여러 종류의 데이터에 대한 캐시를 가지고 있다. JVM에는 애플리케이션의 속도를 향상시키기 위한 여러 종류의 캐시가 있다.
* 캐싱의 기본 아이디어는 간단하다. 캐시는 데이터에 빠르게 접근할 수 있도록 저장된 데이터를 따로 복사하는 것이다.

```kotlin
class WebUserRepository {
    val userClient: UserClient
): UserRepository {
    override suspend fun getUser(id: Int): User =
        userClient.fetchUser(id)
}
```
* 사용자를 조회할 때마다 매번 네트워크 요청을 보내고 응답을 기다려야 한다는 단점이 있다.
* 이전 요청의 결과를 저장해서 특정 아이디의 사용자를 조회할 때마다 네트워크 요청을 보낼 필요가 없게 만든다면 성능을 향상시킬 수 있다.
* 맵을 통해서 다음과 같이 구현할 수 있다.

```kotlin
class CachedWebUserRepository {
    val userClient: UserClient
): UserRepository {

    private val users = ConcurrentHashMap<Int, User>()

    override suspend fun getUser(id: Int): User =
        users.getOrPut(id) { userClient.fetchUser(id) }
}
```
* 위의 예제 코드는 캐시를 간단하게 구현한 예제이다.
* 위의 맵은 여분의 메모리를 나타내는데, 맵을 삭제하더라도 데이터가 실제로 손실되진 않으며, 리포지토리가 다시 데이터를 가져오기만 하면 된다.
* 또한 네트워크 요청을 보낼 필요가 없기 때문에 캐시를 통해 데이터에 빠르게 접근할 수 있음을 알 수 있다.
* 그러나 캐시에는 장점만 있는 것이 절대 아니다. 두 가지 문제가 있다.
  * **첫째, 캐시한 데이터가 변경되면 캐시가 가지고 있는 데이터가 더 이상 유효하지 않다.**
    * 예를 들어, 만약 사용자를 캐시했는데 사용자 이름이 변경되면 캐시에 있는 데이터가 무용지물이 된다.
    * 캐싱 라이브러리(Caffeine 또는 Ehcache)를 사용하면 특정 레코드의 유효 기간을 지정해 캐시를 주기적으로 갱신할 수 있다.
    * 예를 들어, 사용자 레코드의 유효 기간을 1분으로 설정할 수 있다. 지정한 시간이 지나면 사용자 정보를 다시 가져와야 한다. 백엔드에서 자주 변경되지 않는 데이터를 가져오는 경우 유용하게 사용할 수 있다.
  * **둘째, 성능을 얻기 위해 메모리를 낭비할 수 밖에 없다는 것이다.**
    * 너무 많은 데이터를 캐싱하면 메모리가 부족해질 수 있다. 하지만 메모리 문제를 해결할 방법이 여러 가지가 있다.
    * 하나는 사용 빈도가 낮은 캐시 데이터를 만료시키거나(쓰기 후 만료), 캐시 크기를 제한하는 것이다. 가장 좋은 방법은 캐시에 소프트 참조(soft delete)나 약한 참조(weak reference)를 사용하는 것이다.
    * 코틀린에서 변수가 값을 참조하는 것을 강한 참조(strong reference)라고 한다. 가비지 컬렉터는 강한 참조 중인 값을 정리할 수 없다. JVM에서는 강한 참조 대신 두 가지 종류의 참조 방법 또한 제공하고 있다.
    * 가비지 컬렉터는 약한 참조로 된 값을 정리할 수 있다. 따라서 약한 참조 중인 값에 강한 참조가 없는 경우 값을 정리한다.
    * 소프트 참조를 사용하더라도, 다른 참조 방식과 마찬가지로 가비지 컬렉터에 의해 값이 정리될 수는 있으나, 대부분의 JVM 구현체에서는 메모리가 부족하지 않는 한 이 값을 정리하지 않는다.
* 캐시 때문에 메모리가 낭비될 가능성이 있다면 소프트 참조 캐시를 사용하면 된다.
* 소프트 참조 캐시란, 메모리가 충분할 때는 캐시 데이터를 정리하지 않지만, 메모리가 부족할 때는 데이터를 정리해 메모리를 확보한다.

```kotlin
class UserCache {
    private val map = mutableMapOf<Int, SoftReference<User>>()

    fun get(id: Int): User? = map[id]?.get()

    fun put(user: User) {
        map[user.id] = SoftReference(user)
    }
}
```
