# (Effective Kotlin Item 20) Kotlin - 일반적인 알고리즘을 반복하지 말라

#### 일반적인 알고리즘을 반복하지 말라

* 여기서 알고리즘이란, 비즈니스 로직을 포함하지 않으며 별도의 모듈이나 라이브러리로 추출할 수 있다.
* 짧지만 반복적인 알고리즘을 추출하면 다음과 같은 장점을 얻을 수 있다.
  * 알고리즘을 구현하는 것보다 한 번 호출하는 게 쉽기 때문에 프로그래밍이 빨라진다.
  * 이름이 지정되므로 구현을 읽는 대신 이름으로 알고리즘을 인식할 수 있다. 해당 알고리즘에 익숙한 개발자는 이름만으로 알고리즘을 쉽게 떠올릴 것이다.
  * 이상한 부분이나 예외적인 부분이 좀 더 쉽게 식별될 수 있다. `sortedBy`나 `sortedByDescending`의 다른 점을 생각해보자. 두 함수를 호출할 때 내용이 거의 비슷하더라도 정렬 방향은 명확히 구분된다. 매번 이 로직을 구현해야 한다면 구현된 정렬이 오름차순인지 내림차순인지 혼동하기 쉽다.
  * 한 번 최적화되면 추출한 함수를 사용하는 모든 곳에서 최적화의 이점을 얻을 수 있다.

#### 표준 라이브러리를 배워라

* 일반적인 알고리즘은 이미 다른 사람에 의해 정의되어 있는 경우가 대부분이다.
* 표준 라이브러리를 사용하면 직접 구현하지 않고도 활용할 수 있다.

#### 자신만의 유틸리티 구현하기

* 모든 프로젝트의 어느 시점에는 표준 라이브러리에 없는 알고리즘이 필요하다.

```kotlin
fun Iterable<Int>.product() = fold(1) { acc, i -> acc * i}
```

* 여러 번 사용되지 않는다고 해도 함수로 추출하는 것이 좋다.
* 확장 함수는 다음과 같은 이유로 정말 선택이니 강력히 권장한다.
  * 함수는 상태를 유지하지 않으므로 동작을 표현하는 데 적합하다. 특히 사이드 이펙트가 없는 경우 적합하다.
  * 다른 최상위 함수에 비해 확장 함수는 구체적인 타입의 객체에만 제안되므로 더 좋다.
  * 인수보다 확장 리시버를 수정하는 것이 더 직관적이다.
  * 확장 함수는 객체에 대해 자동 완성 기능으로 제안되므로 동반 객체나 정적 메서드에 비해 찾기 쉽다.
  * 메서드를 호출할 때 최상위 함수를 클래스 또는 슈퍼클래스의 메서드와 혼동하기 쉽지만 예상되는 동작은 매우 다르다. 최상위 확장 함수는 객체에서 호출되어야 하므로 이런 문제가 없다.
