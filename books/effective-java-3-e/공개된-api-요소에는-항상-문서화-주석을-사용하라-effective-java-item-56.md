# (Effective Java Item 56) Java ‐ 공개된 API 요소에는 항상 문서화 주석을 사용하라

#### JavaDoc 주석 유의사항

* 자바독(JavaDoc)이란, API 문서화 유틸리티로 소스코드 파일에서 문서화 주석이라는 특수 형태로 기술된 설명을 추려 API 문서로 변환해주는 것을 말한다.

#### API를 올바르게 문서화하려면 공개된 모든 클래스, 인터페이스, 메서드, 필드 선언에 문서화 주석을 달아야 한다.
* 만약 주석을 달지 않으면 그저 공개된 API 요소들의 선언만을 나열하게 된다.
* 공개 클래스는 기본 생성자에 주석을 달 수 없기에 절대 기본 생성자를 사용해선 안 된다.

#### 메서드용 문서화 주석에는 해당 메서드와 클라이언트 사이의 규약을 명료하게 기술해야만 한다.
* how가 아닌 what을 기술한다.
* 메서드를 성공적으로 호출하기 위한 전제 조건을 나열한다.
* 메서드가 성공적으로 수행된 후 일어나게 되는 사후 조건을 나열한다.
* 부작용(시스템 상태에 변화를 가져오는 것)도 문서화를 해야한다.

#### JavaDoc 명령어 커맨드라인
```shell
$ javadoc -d docs {file_name}
```

#### 한글 사용 시 UTF-8로 인코딩 필요
```shell
$ javadoc -d docs *.java -encoding UTF-8 -charset UTF-8 -docencoding UTF-8
```

#### JavaDoc 주석 태그 종류

* `@Param` : 매개변수를 뜻하는 명사구. 모든 매개변수에 설명을 달아야 한다.
* `@return` : 반환 값을 설명하는 명사구. 반환 타입이 void가 아니라면 달아야 한다.
* `@throws` : if로 시작해서 해당 예외를 던지게 되는 조건을 설명한다.
* `{@code}` : 주석 내에 HTML 요소나 다른 자바독 태그를 무시한다. 주석에 여러 줄로 작성된 코드 예시를 넣으려면 `{@code}`를 `<pre>`태그로 감싸준다.
* `{@literal}` : 주석 내에 HTML 요소나 다른 자바독 태그를 무시한다. `{@code}`와 비슷하지만 코드 폰트로 렌더링하지 않는다.
* `@implSpec` : 해당 메서드와 하위 클래스 사이의 계약을 설명한다. 하위 클래스들이 그 메서드를 상속하거나 super 키워드를 이용해 호출할 때 그 메서드가 어떻게 동작하는지 명확히 인지할 수 있도록 도와준다.
* `{@inheritDoc}` : 상위 타입 문서화 주석 일부를 상속할 수 있다.

#### API 문서화에서 자주 누락되는 설명 2가지를 포함하자.

* 클래스 혹은 정적 메서드가 쓰레드 안전(thread-safe)하든 그렇지 않든, 쓰레드 안전 수준을 반드시 API 설명에 포함시켜야 한다.
* 직렬화할 수 있는 클래스라면 직렬화 형태도 API 설명에 기술해야 한다.
* **문서화 주석은 API를 문서화하는 가장 훌륭하고 효과적인 방법이다.**
* **public API라면 빠짐없이 설명을 달아야 한다.**
* **표준 규약을 일관되게 지켜야 한다.**
* **문서화 주석에 임의의 HTML 태그를 사용할 수 있음을 기억하라. 단, HTML 메타문자는 특별하게 취급해야 한다.**
