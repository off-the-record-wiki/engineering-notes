# Claude Code - Course Wrap-Up: Building and Deploying Custom Plugins and Skills

#### 반복 작업을 Skills로 나누고 Plugin 패키지 결합

* 지침과 스킬의 차이 및 컨텍스트 비용 : 지침은 세션을 시작할 때 항상 읽혀 프로젝트의 전반적인 규칙을 적용하고 스킬은 특정 작업을 요청할 때만 불러온다. 자주 쓰지만 매번 필요하지 않은 절차를 스킬로 분리하면 불필요한 컨텍스트와 토큰 사용을 줄일 수 있다.
* 스킬 작성 규칙과 Skill.md 구조 : 반복되는 작업 절차를 스킬로 만들 때는 지침에 이미 있는 내용을 중복하지 않고 작업 고유의 순서만 담는다. 스킬은 `.claude/skills/[스킬이름]/Skill.md`에 저장하며 AI가 용도와 호출 조건을 알 수 있도록 Description을 명확하게 작성한다.
* 플러그인 패키징과 폴더 구조 : 훅, 서브에이전트 정의, 스킬 등을 플러그인으로 묶으면 다른 프로젝트에서도 재사용할 수 있다. 권한 규칙은 플러그인에 직접 담을 수 없어 훅으로 적용하고 프로젝트별 설정이나 지침 문서는 플러그인에 포함하지 않으며 `plugin.json`에 이름과 설명을 기록한다.
* 로컬 플러그인 설치 테스트와 호출 방식 : 빈 폴더에서 Claude Code를 실행하고 설정에 로컬 플러그인 경로를 지정해 설치를 확인한다. `/plugins`는 공식 마켓플레이스 목록을 보여주므로 로컬 플러그인은 `/context`로 확인하고 플러그인에 포함된 스킬은 플러그인 이름이 붙은 형태로 호출한다.
* 외부 플러그인 보안과 MCP의 비용·안정성 이슈 : 로컬에서 명령을 실행하는 플러그인과 외부 서버에 연결하는 MCP는 위험 요소가 다르다. 낯선 플러그인의 훅은 실행 명령과 권한을 검토해야 하고 MCP는 사용하지 않는 도구 설명도 컨텍스트에 상주해 토큰 비용이 발생하므로 외부 응답의 안전성과 세션 내 승인 절차도 고려해야한다.

#### 하네스를 통한 궁극적 제어

* 하네스 규칙과 플러그인 이전 : 기존 프로젝트에서 사용하던 플러그인과 지침을 새 프로젝트에 복사해 재사용하는 방법을 다룬다. `trusted`와 `external import`는 제외하고 `context`를 확인해 플러그인이 제대로 로드됐는지 검증한다.
* 프로젝트별 지침 수정과 서브 에이전트 역할 분담 : `CLAUDE.md`의 공통 규칙은 유지하고 새 프로젝트에 필요한 지침만 바꿔 구현한다. 조사·구현·테스트·검토를 서브 에이전트에 나누어 맡기고 필요한 대화를 직접 유연하게 이끌어가는 방식을 적용한다.
* AI 에이전트 제어의 네 가지 핵심 요소 : 비용, 안전, 워커, 롤백을 중심으로 에이전트 운영의 핵심을 정리한다. 대화 이력과 캐시로 비용을 관리하고 훅과 샌드박스로 위험을 줄이며 역할 분담 기준과 작업 롤백 방법도 마련해야한다.
* 하네스로 예측 가능한 작업 범위 만들기 : 에이전트가 매번 다르게 행동하더라도 지침·훅·플러그인으로 규격과 바운더리를 정하면 그 범위 안에서 동작하도록 제어할 수 있다. 기존에 만든 키트를 실제 프로젝트에 옮긴 뒤 각 프로젝트의 규칙에 맞게 다듬는 것이 중요하다.
