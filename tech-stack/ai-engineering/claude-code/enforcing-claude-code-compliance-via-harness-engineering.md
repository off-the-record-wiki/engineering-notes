# Claude Code - Enforcing Claude Code Compliance via Harness Engineering

#### 결과 품질과 검증 관점과 Hook을 통해서 자동화

* AI 에이전트의 자기 선호 편향과 완료 조건 : Claude Code는 오류나 누락이 있어도 작업을 마쳤다고 판단할 수 있다.
* 검사 명령 파일과 종료 코드 기반 검증 : 지침 파일에 실행 및 검사 명령을 정해 두고 검사 결과를 종료 코드로 확인한다. 정상은 0, 비정상은 0이 아닌 값으로 판별하고 종료 코드가 0이 될 때까지 Claude Code에 수정을 요청한다.
* Hook을 이용한 검사 자동화 : Claude Code의 응답 종료 시점인 Stop 이벤트에 Hook을 설정해 검사를 자동으로 실행한다. `.claude/settings.json`에 Hook을 등록하고 동작 여부를 확인하는 과정을 거친다.
* Hook 동작 확인과 트레이드오프 : 코드 수정 후 `.claude/hook-log.txt`에 기록이 남는지 확인해 Hook의 자동 실행을 검증한다. 검사를 자주 실행할수록 작업이 느려질 수 있으므로 필요한 Hook을 선별한다.

#### retry loop & block & notofication Hook 모두 적용

* 재시도 루프와 상한 설정 : 검사에 실패하면 Claude Code가 작업을 보완해 다시 검사를 받도록 재시도 루프를 구현한다. 무한 반복에 다른 비용과 시간 낭비를 막기 위해 재시도 횟수에 상한을 두고 처음에는 낮은 값부터 설정한다.
* 재시도 루프 실습 및 검증 : `.claude/hook-log.txt`에 재시도 횟수를 기록하고 상한을 3으로 설정해 동작을 확인한다. 통과할 수 없는 조건을 만들어 3번 시도 후 멈추는지 검증한 다음 마지막 저장 상태로 롤백해 환경을 초기화한다.
* 명령 실행 전 차단 훅 도입 : 명령 실행 후 작동하는 Stop 훅으로는 파일 삭제 같은 위험한 작업을 막기 어렵다. 그래서 `PreToolUse` 훅을 추가해 `rm`처럼 되돌리기 힘든 명령을 실행 전에 차단하고 `settings.json`을 수정한 뒤 기존 설정이 덮어써지지 않았는지 확인한다.
* 알림 및 기록 훅과 트레이드오프 : 차단할 정도는 아니지만 확인이 필요한 작업은 `danger-log.txt`에 기록하도록 구성한다. 규격을 엄격하게 관리하면 안전성은 높아지지만 생산성과 작업 속도가 낮아질 수 있으며 로그를 바탕으로 조직 차원의 Gateway나 Proxy 모니터링으로도 확장할 수 있다.
* 정적 검증 한계 : 명령어에 특정 문자열이 포함되었는가 확인하는 정적 검증은 표현을 바꾸면 우회될 수 있다. 그래서 허용 목록과 거부 목록을 활용해 명령 실행을 통제한다.
