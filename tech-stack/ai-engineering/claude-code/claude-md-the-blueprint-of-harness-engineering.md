# Claude Code - CLAUDE.md: The Blueprint of Harness Engineering

#### 지침이 필요한 이유(CLAUDE.md)

| 요청에 적은 것 | 적지 않은 것 |
| :---: | :---: |
| 4개의 부분으로 나눌 것 | 파일 이름과 개수 |
| 브라우저에서 바로 열릴 것 | 네 덩어리의 순서 |
| - | 표로 낼지 목록으로 낼지 |
| - | 쓰는 언어와 파일 형식 |

* 동일한 프롬프트 결과 비교 : 서로 다른 폴더와 새로운 세션에서 같은 프롬프트를 실행해 결과물을 비교하면 결과가 다르다. AI 에이전트의 비결정성을 확인할 수 있다.
* 세션의 상태성과 비교 시 주의점 : 새로운 세션의 AI 에이전트는 프로젝트 맥락이나 사용자의 취향을 모르기 때문에 세부 사항을 스스로 판단한다. 같은 세션에서 결과가 비슷해지는 것은 이전 대화의 결과를 기억하기 때문이므로 공정하게 비교하려면 새로운 세션을 사용해야 한다.
* `CLAUDE.md`로 지침 적용 : 매번 프롬프트에 지침을 넣으면 요청이 길어지고 인풋 토큰 비용도 증가한다. 프로젝트 폴더에 `CLAUDE.md`를 두면 Claude Code가 실행될 때 지침을 자동으로 읽도록 할 수 있다.
* 지침 작성 기준과 토큰 비용 : 프로젝트 목적이나 결과물 조건처럼 내일도 유효한 규칙은 지침에 기록하고 일회성 작업은 프롬프트로 요청한다. 지침은 매 요청마다 토큰으로 소비되므로 짧고 명확하게 작성해야 하며, 실험에 사용한 폴더와 세션은 정리한 뒤 기존 작업 환경으로 돌아간다.

#### 모든 작업은 Claude Code를 통해서 진행한다.

* 지침 파일의 역할과 구조 : 여러 프로젝트에 적용할 공통 규칙과 특정 프로젝트에만 필요한 규칙을 구분하며, 파일 형식을 몰라도 Claude Code가 작성 가능하다.
* 프로젝트 규칙과 정보 선별 기준 : 검색으로 쉽게 확인할 수 있는 일반 정보나 기준표는 빼고 자료가 누락된 경우에는 누락 이유와 판단에 미치는 영향까지 밝혀 빈 부분도 정보가 되도록 한다.
* 결과물 조건과 언어 미지정 : 실행 명령, 검사 명령, 브라우저 실행, 추가 설치 없이 실행이라는 4가지 조건을 공통 규칙으로 설정한다. 특정 언어나 프레임워크를 지정하지 않으면 다양한 프로젝트에 적용하기 쉽고 검사 방식도 단순해진다.
* 생성된 지침 파일 검토와 정리 : 지침 생성 프롬프트에 언어를 제한하지 말고 간결하게 작성하라는 조건을 넣는다. 생성된 파일을 확인하면서 불필요한 코딩 규칙, 특정 도구 이름, 당연한 지시사항을 지워 지침을 짧고 실용적으로 다듬는다.
* 프롬프트 실행과 Claude Code 동작 확인 : 완성한 지침을 바탕으로 작업 시작 전 알림과 내부 스킬 자동 임포트를 확인한다. 또한 `CLAUDE.md`가 세션마다 자동으로 로드되므로 별도의 메모리 적재 명령은 필요하지 않다는 점을 명시한다.
* `CLAUDE.md`의 목적 : `CLAUDE.md`는 매번 프롬프트에 입력할 규칙을 미리 정의해 두는 도구이다. 공통 규칙과 프로젝트별 규칙을 적절히 나누고 지침을 간결하게 유지하면 일관된 결과물을 얻는 데 도움이 된다.

#### AI Agent의 지침 계층과 Context, Memory 구조

* 지침의 3가지 계층과 적용 방식 : 전역 지침, 프로젝트 지침, 개인 지침은 각기 다른 위치에 저장된다. 전역에는 개인 취향, 프로젝트에는 공유할 프로젝트 규칙, 개인 지침에는 해당 프로젝트에서 나에게만 적용할 설정을 적는다.
* 지침을 둘 위치를 정하는 기준과 주의사항 : 이 설정이 나를 위한 것인지 프로젝트를 위한 것인지에 따라 지침 위치를 정한다. 전역 지침에 프로젝트 규칙을 두면 다른 프로젝트에까지 적용될 수 있고, 개인 설정 파일이 공유되지 않도록 확인해야 한다.
* 지침과 기억의 차이 : 지침은 사용자가 파일에 직접 작성하는 규칙으로 매번 읽히며 완벽한 강제라기보다 권고에 가깝다. 기억은 대화에서 나온 사실을 바탕으로 별도 파일에 쌓인다.
* `memory` 명령으로 현재 컨텍스트 확인 : `memory` 명령어를 사용하면 현재 세션에서 읽히는 지침 파일과 기억 파일을 확인할 수 있다. 목록에 전역 지침, 프로젝트의 `CLAUDE.md`, 오토 메모리 등이 표시되는지 점검한다.
* `@` 기호로 파일 점검 : 지침 파일에서 `@파일경로`와 같은 형식으로 다른 파일을 불러오면 규칙을 주제별로 나눠 관리하기 쉽다. 다만 파일을 나누더라도 입력되는 내용은 같아서 컨텍스트 사용량을 줄여주지는 않는다.

#### 지침 길이에 따른 비용과 그에 따른 Memory 상관 관계

* 지침 파일의 길이와 토큰 비용 : 지침 파일은 한 번 읽히고 끝나는 것이 아니라 요청할 때마다 컨텍스트에 실린다. 파일을 길게 만들면 토큰 사용량이 늘어나고 이 비용이 요청마다 반복된다.
* 지침이 길어질 때 생기는 문제 : 규칙이 많아지면 AI가 일부를 놓치거나 서로 충돌하는 규칙을 따를 수 있다. 규칙이 적을 때보다 많은 내용을 안정적으로 기억하고 적용하기 어렵다.
* 효율적인 지침 작성과 관리 원칙 : 문제가 생길 때 필요한 규칙만 남기고, 당연한 내용이나 잘 지켜지지 않는 예시 코드는 제외한다. 규칙을 폴더별로 나누고 정기적으로 불필요한 내용을 정리하면 평소 컨텍스트 사용량을 줄일 수 있다.
* 메인 세션 특성 : 메인 세션은 매번 처음부터 판단하는 상태라 같은 요청도 다르게 처리될 수 있고 지침 문서가 이를 보완한다. 다만 지침만으로 한 번에 너무 많은 작업을 해결할 수는 없다.
