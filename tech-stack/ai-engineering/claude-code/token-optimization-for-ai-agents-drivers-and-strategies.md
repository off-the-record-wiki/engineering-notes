# Claude Code - Token Optimization for AI Agents: Drivers and Strategies

#### 사용에 따른 토큰 비용 구조와 Message 누적 비용 압축 및 없애기

* 토큰 비용 구조와 사용량 확인 : 토큰은 Claude가 글을 읽고 쓰는 기본 단위이며, 요청과 대화 이력, 읽은 파일 등이 입력 비용에 포함된다. `usage`나 cost` 명령어로 사용량을 확인할 수 있고 `CurrentSession`은 열린 대화가 아니라 요금제 리밋을 계산하는 시간 단위이다.
* 컨텍스트 구성 요소와 토큰 점유율 : 지침 파일, 대화, 읽은 파일과 명령 결과가 `messages`에 묶여 컨텍스트를 구성한다. 시스템 프롬프트와 MCP, SKILLS와 같은 툴 디스크립션은 사용자가 임의로 줄일 수 없으며 `tokens` 항목에서 각 구성 요소의 점유 비율을 확인할 수 있다.
* 메시지 누적 문제와 `compact` 명령어 : Claude는 프롬프트를 요청할 때마다 세션 이력을 다시 읽기 때문에 대화가 길어지면 응답이 느려지고 비용도 비효율적으로 늘어날 수 있다. `compact`는 대화를 요약해 `messages`를 압축하지만 실행 자체에도 토큰 비용이 들며, 커스텀 요약 지시로 코드 변경 사항 등 특정 내용에 집중하게 할 수 있다.
* `clear` 명령어와 세션 관리 기준 : `clear`는 대화 이력을 비우고 세션을 초기화한다. 같은 작업을 이어갈 때는 `compact`로 맥락을 유지하고 다른 작업으로 넘어갈 때는 이전 대화 흔적이 섞이지 않도록 `clear`를 사용하는 것이 좋다. 결과물이 파일로 남아 있다면 세션에서 파일을 다시 열어 참고할 수 있고, Claude Code가 컨텍스트가 켜졌을 때 자동으로 압축하기도 한다.

#### 출력 관점의 최적화와 AI Agent의 캐시 최적화를 위한 패턴

* 파일 읽기 범위와 messages 최적화 : 파일이나 명령 실행 결과가 대화 이력에 쌓이므로 파일 전체를 읽을 때와 필요한 부분만 읽을 때의 messages 증가량이 다르다. 필요한 영역만 읽도록 지시하면 불필요한 컨텍스트 부피를 줄일 수 있다.
* 출력 토큰 절감을 위한 프롬프트 패턴 : 원문을 답변에 그대로 반복하지 않고 요약하도록 지시하면 출력 토큰의 중복 소모를 막을 수 있다. 다만 세밀한 최적화가 개발자의 생산성을 떨어뜨릴 수 있다.
* 캐시 메커니즘과 반복 비용 최적화 : 지침 파일이나 기존 대화처럼 매 요청에서 반복되는 입력은 캐시 쓰기와 읽기를 통해 더 저렴하게 처리된다. 반복 입력 캐시를 유지하는 것이 비용 절감에 중요하다.
* 캐시 깨짐 방지와 TTL 관리 : 모델 변경, 지침 파일 수정, `/compact` 실행은 기존 캐시를 무효화할 수 있으므로 수정 사항을 모아 반영하고 모델 변경은 작업 단위가 끝난 뒤 하는 편이 좋다. 캐시는 TTL이 있는 휘발성 데이터라 요청이 오랫동안 없으면 만료될 수 있다.
* 컨텍스트 규격 문서 분리와 관리 : `/usage`, `/context` 등의 명령어와 관리 규칙은 `CLAUDE.md`에 모두 넣기보다 별도의 참고 문서로 분리해 필요할 때만 읽게 한다. 이렇게 하면 항상 불러오는 지침 파일 길이를 줄일 수 있다.
