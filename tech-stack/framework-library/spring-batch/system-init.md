# Spring Batch - SYSTEM INIT

#### 배치 처리란?

* 배치(Batch) 처리는 대량의 데이터를 정해진 시간에 자동으로 일괄 처리하고 결과를 출력하는 작업을 말한다.
* 배치 처리의 특징
  * 대용량 데이터 처리 : 배치는 대량의 데이터를 효율적으로 처리한다. 웹 애플리케이션이 특정 ID의 데이터 하나를 조회하거나 수정한다면 배치는 수천, 수만 개의 데이터를 한 번에 처리한다.
  * 정기적 실행 : 매일, 매주, 매달 등 정해진 시간에 실행된다.
  * 자동화 : 한 번 만들고 설정해두면 알아서 모든 것을 처리한다.
  * 무인 처리 : 사람이 옆에서 지켜보지 않아도 된다.
  * 유한한 양의 데이터 처리 : 배치는 정해진 양의 데이터만 처리한다.
  * 예측 가능한 부하 처리 : 배치는 시스템의 처리 능력에 맞게 설계된다. 시스템이 감당할 수 있는 만큼의 데이터만 처리하도록 설계해야 한다.

#### 실무 배치 사례들

* 일일 정산 배치(Daily Settlement) : 매일 밤 자정 어김없이 실행된다. 하루 동안의 거래 내역, 결제 정보, 사용자 활동 로그를 모두 정리하고 집계한다. 시스템의 가장 기본적이고 중요한 처리 작업이다.
* 대용량 데이터 마이그레이션 : 시스템 업그레이드나 DB 변경 시 수행되는 작업이다. 수백만, 수천만 건의 데이터를 새로운 저장소로 안전하게 이동시켜야 한다. 한 번의 실수가 전체 시스템을 마비시키는 고난도 작업이다.
* 리포트 생성 배치(Report Generation) : 데이터를 모아 주기적으로 리포트를 만들어낸다. 이 리포트는 보통 이메일, 알림 메시지 등의 형태로 전달되며, 중요한 결정을 내리는 데 필요한 정보를 제공하는 데 사용된다.
* 데이터 정제 배치(Data Cleansing) : 중복된 데이터를 제거하거나 형식을 통일하여 데이터 품질을 개선하는 작업이다. 이 배치는 오래된 데이터나 부정확한 데이터를 정리해 시스템 성능과 신뢰성을 높이는 데 기여한다.
* 백업 배치(Regular Backup) : 정기적으로 데이터를 백업하여 시스템 장애나 데이터 손실에 대비하는 작업이다. 이 과정은 예기치 못한 문제 발생 시 데이터를 복구하고 서비스를 빠르게 정상화하기 위한 안전망 역할을 한다.
* 데이터 통합 배치(Data Integration) : 여러 데이터 저장소에서 데이터를 수집하여 하나의 일관된 데이터 상태로 만드는 대규모 작업이다. 이 과정은 데이터의 정합성을 유지하고 다양한 서비스에서 통합된 최신 데이터를 활용할 수 있도록 한다.

#### 웹 vs 배치: 무엇이 다른가?

![](https://github.com/user-attachments/assets/a6264342-9e95-4b9d-b75f-7715bf029532)

* 웹: 사용자가 요청하면 즉각적으로 처리한다. 클릭하거나 데이터를 입력하면 그 순간 서버가 요청을 받아 JSON, HTML 등의 결과를 돌려준다. 이게 웹 애플리케이션의 본질이다. 실시간 반응이 핵심이다.
* 배치: 배치는 사용자의 요청을 기다리지 않는다. 정해진 스케줄에 따라 작업이 자동으로 실행된다.

![](https://github.com/user-attachments/assets/a434df58-b16c-4dbd-b74f-ddae57c536ad)

* 웹: 사용자 요청에 즉각 응답하는 것이 생명이다. 페이지 로딩이 1초만 느려져도 사용자는 떠난다. 실시간 피드백이 가장 중요하다.
* 배치: 배치에서는 결과의 속도보다 정확성과 완결성이 우선이다. 데이터 처리에 시간이 걸리더라도 대량 데이터를 완벽하게 처리하는 것이 목표다.

![](https://github.com/user-attachments/assets/07e5d009-3e15-4b60-85d5-95d24da3b03c)

* 웹: 잘못된 요청이 오면 즉시 에러 코드를 반환하고 끝낸다. 사용자에게 문제를 알리고 서버는 다음 요청을 기다린다.
* 배치: 배치는 복구에 초점을 맞춘다. 문제가 발생하면 재시도하고 실패가 반복되면 중단한 뒤 로그와 알림으로 관리자를 호출한다. 문제를 해결한 후 실패한 작업을 재시작하는 것이 일반적이다.

![](https://github.com/user-attachments/assets/1dfa6df9-ca7d-40c6-b8c0-457a70227800)

* 웹: 서버는 상시 실행 중이다. 사용자가 요청하지 않는 시간에도 대기 상태로 유지되며 메모리와 CPU를 지속적으로 사용한다.
* 배치: 배치는 필요할 때만 실행된다. 작업이 끝나면 리소스를 반환하고 종료된다.

#### Spring Batch 필요성

1. 유지보수성

* 배치 코드는 오래 간다. 웹 애플리케이션은 비즈니스 요구사항 따라 자주 수정되지만 배치 처리는 한번 정립된 업무 프로세스를 수행하기 때문에 상대적으로 변경이 적다. 그만큼 한 번 만들 때 신중해야 한다.

2. 유연한 데이터 처리

![](https://github.com/user-attachments/assets/59950194-681f-4f82-a121-eb1165584a73)

* 스프링 배치는 다음과 같은 다양한 데이터 소스를 기본적으로 지원한다. 플랫 파일(CSV, TXT), XML/JSON, 관계형 데이터베이스, NoSQL, 메시징 시스템에 대해서 지원한다.

3. 견고한 트랜잭션 관리

* 체크포인트 : 긴 배치 작업 중간에 안전 지점을 설정. 문제 발생 시 처음이 아닌 마지막 체크포인트부터 재시작 가능하다.
* 유연한 트랜잭션 범위 설정 : 처리할 데이터 양과 특성에 따라 트랜잭션 범위 조절 가능. 작은 단위의 커밋으로 메모리 사용량 조절이 가능하다.

4. 재시작 기능과 유연한 실행 제어

* 재시작 기능: 대용량 데이터 처리 중 실패해도 처음부터 다시 시작할 필요가 없다. 오류 발생 시 마지막으로 성공한 Step부터 재시작 가능하며 Step 내에서도 마지막 처리 항목 이후부터 작업 재개가 가능하다.
* 유연한 실행 제어 : 특정 Step만 선택적으로 실행 가능하다. 파라미터를 통한 동적 작업 제어와 Step의 조건부 실행을 지원한다.
* 작업 상태 추적 : 모든 Job과 Step의 실행 상태를 메타데이터로 관리한다. 작업의 실행 시점과 결과를 정확하게 추적 가능하다.

#### 대용량 데이터 처리와 확장성

![](https://github.com/user-attachments/assets/44b9b5ed-9bb6-49fe-ae6d-dcc915bf13d6)

* Chunk 지향 처리 : 대량의 데이터를 지정된 크기로 나누어 순차적으로 처리. 한 번에 처리하는 데이터양을 제한하여 메모리 사용 최적화도 가능하다.
* 확장성 기법(Scalability Techniques) : 멀티쓰레드 Step, 병렬 Step, 분산 처리를 지원한다.
* 효율적인 데이터 읽기 : 페이징 방식과 커서 방식을 지원한다.

#### Job과 Step

![](https://github.com/user-attachments/assets/94954ff1-2abb-4cc5-89a3-c6ce3d9614df)

* Job은 하나의 완전한 배치 처리를 의미한다. 실제로 우리가 흔히 접하는 배치 작업들은 모두 Job으로 표현한다.
* Step은 Job을 구성하는 실행 단위로 하나의 Job은 하나 이상의 Step으로 구성된다.
